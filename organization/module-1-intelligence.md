# 模块1：情报与素材部

## 职责边界

模块1负责回答两个问题：**发生了什么**、**该用哪段素材**。

- 输入：钦定资源与跟踪资源（`resources/registry.json`）、各平台消息源；
- 输出：一份事件归纳 + 一份选定的视频源清单，交给模块2刻录；
- 不做：字幕、翻译、刻录、发布，也不修改资源登记或巡检结论。

模块1是模块2的**唯一上游**。模块2不得自行选题，也不得推翻模块1的素材选择；
模块1不得越权刻录或发布。

## 视频源监测及消息获取处

### 最小间隔

按最高指示 3.8：监测按平台可用的**最小调度间隔**执行。GitHub Actions 的最短
定时调度是 5 分钟，因此监测工作流的 cron 固定为 `*/5 * * * *`，不得以节省额度
为由放宽。放宽须按第六条书面批准并登记有效期。

### 监测范围

包含不限于：

- 钦定 YouTube 频道：`@WhiteHouse/streams`、`@WhiteHouse/videos`（必须常开）；
- 其他 YouTube 频道与单条素材（WWMT 等）；
- 社交平台账号与话题；
- 新闻站点与 RSS、通讯社与聚合源；
- 搜索来源（按事件关键词增量检索）。

一条来源一条记录，采集器必须真实存在；声明了却无法采集的按登记不实处理。

### 判定与交接

1. 拉取最新上传，与 `.github/state/whitehouse-processed-videos.txt` 台账比对；
2. 未处理的最新素材 → 写入台账并触发 `auto-pipeline`；
3. 采集失败记为 `unknown`，不得记为 `ok`（第七条）；
4. 同一素材不得重复触发；重复触发按 P2 处理。

扫描顺序（2026-10-30 授权调整）：定时扫描先查 `@WhiteHouse/videos`；该处没有未处理
上传时，才由手动运行以 `include_streams=true` 追加 `@WhiteHouse/streams`。直播条目在
结束前不能成片，先扫 `streams` 会占掉 5 分钟调度窗口。两个钦定频道仍由
`scripts/monitoring/acquisition.py` 按最小间隔登记，钦定来源不因该调整断开。

### 实现

|---|---|
| 定时监测 | `.github/workflows/monitor-whitehouse.yml`（cron `*/5 * * * *`） |
| 采集器 | `scripts/monitoring/acquisition.py` |
| 台账 | `.github/state/whitehouse-processed-videos.txt` |

## 事件归纳分析处

### 分析范围

包含不限于社交平台、视频、新闻与搜索。每个事件至少回答：

| 字段 | 要求 |
|---|---|
| 事件摘要 | 一句话说明发生了什么、何时、何地、涉及谁 |
| 背景 | 事件所处的政策、选举、司法或国际背景 |
| 时间线 | 按时间排序的关键节点，每节点带来源与时间戳 |
| 前因 | 直接触发因素与更早的结构性原因分开写 |
| 后果与影响 | 已发生的影响与合理推断的影响分开写，推断须标注 |
| 各方立场 | 主要行为体的公开表态，注明来源与时间 |
| 多源交叉验证 | 同一事实至少两个独立来源；只有单一来源的标 `single-source` |
| 未证实项 | 传闻、匿名消息、AI 生成内容单列，不得混入结论 |
| 素材建议 | 建议的拍摄角度、时间区间与候选来源 |

### 方法与红线

1. **多源交叉**：同一事实至少两个独立来源；官方通稿与转载同一通稿不算两个来源；
2. **时间线可复核**：每个节点必须有 URL 与抓取时间；
3. **推断标注**：影响与因果推断必须与已证实事实分开，禁止把推测写成结论；
4. **不伪造**：不得编造引语、时间或来源；无法核实就写 `未证实`；
5. **留痕**：归纳写入 `docs/events/<event-id>.md`，并在交付报告中引用。

### 实现

| 环节 | 实现 |
|---|---|
| 事件核验 | `scripts/verify_event.py`（写入 `work/EVENT.json`） |
| 多源研究 | `scripts/infogap/generate.py`（信息差报告，含多源检索） |
| 产出 | `docs/events/<event-id>.md`（模板见 `docs/events/TEMPLATE.md`） |

## 素材获取处

### 素材标准

以下条件同时成立才算合格素材：

| 条件 | 判定 | 不满足的后果 |
|---|---|---|
| 干净 | 无横幅遮挡、无无关水印/台标压字、无黑场 | 降级或换源 |
| 可信 | 钦定频道或高信任来源；有原始发布页 | 不得作为主素材 |
| 多角度/特色 | 同一事件至少两个独立机位/来源；或单机位但画面/信息具有不可替代的独特价值 | 单机位且无特色须声明 |
| 足够长 | 覆盖事件完整过程，优先最长可用版本 | 短片段只能做补充 |
| 自带字幕 | 优先官方或自动字幕轨；缺失时允许 ASR 兜底 | ASR 须标注来源、引擎与置信度 |
| 非静止/无关 | 有持续画面运动与有效内容，不是冻结帧、静态图或无关空镜 | 直接淘汰 |

字幕条件不计入 100 分，但缺失且未做 ASR 的素材不得进入刻录。

按最高指示 2.2、3.6，视频/音频来源获取属于模块1素材获取职责；取得已选素材的
音频副本供后续字幕处理仍归模块1，不得将下载命令划入模块2。人工命令入口为
`scripts/manual_youtube_commands.ps1` 第 11 步；只下载并提取音频，不执行 ASR 或翻译。

### 100 分口径

| 维度 | 权重 | 计分 |
|---|---:|---|
| 时长 | 20 | `min(时长 / 目标时长, 1) × 20`，目标默认 90 分钟 |
| 动态有效 | 25 | 冻结比例 ≤2% 满分；>35% 直接不合格；按冻结与黑场比例线性扣分 |
| 干净 | 20 | 黑场比例 ≤1% 满分；>20% 不合格 |
| 可信 | 20 | 沿用来源信任表：白宫/C-SPAN 20，通讯社 18，主流电视网 12–16 |
| 多角度 | 15 | 3 个以上独立来源 15；2 个 12；单来源 6 |

及格线 60 分，且冻结比例、黑场比例必须同时达标，时长不得低于目标时长的 25%
（默认约 22.5 分钟）。任何降级都要写入 `FOOTAGE.json` 与交付报告。

### 实现

| 环节 | 实现 |
|---|---|
| 候选源排序 | `scripts/rank_video_sources.py`（时长 30 / 分辨率 25 / 标题 15 / 热度 10 / 信任 20） |
| 画面质量抽检 | `scripts/footage_quality.py`（抽帧检测冻结、黑场、场景切换，输出 `FOOTAGE.json`） |
| 人工音频获取 | `scripts/manual_youtube_commands.ps1` 第 11 步（yt-dlp 提取所选来源音频；遵循 DIRECTIVE.md 3.6 的执行位置要求） |
| 字幕区遮挡 | 由模块2在刻录时判定（需要真实帧） |

`footage_quality.py` 只做**抽检**：默认在视频上均匀取 6 段、每段 20 秒，统计
`freezedetect`、`blackdetect` 与场景切换数。抽检结论用于淘汰静止/无关画面，
不等价于逐帧审片。

## 交接给模块2

模块1交付时必须同时给出：

1. 事件归纳路径与 `single-source` / `未证实` 标记；
2. 选定视频的 ID、URL、时长、分辨率与来源信任分；
3. `SOURCES.json`（候选与分数）与 `FOOTAGE.json`（画面抽检）；
4. 语言与字幕预期（是否已有官方字幕轨）。

缺少任一项，模块2不得开工；模块2发现素材不达标时应退回模块1，而不是自行换源。

## 复核方式

```bash
python scripts/resources/check.py check
python scripts/inspection/plan.py check --github
python scripts/footage_quality.py --video work/<id>.source.mp4 --report work/FOOTAGE.json
```
